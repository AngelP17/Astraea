# Astraea

[![CI](https://github.com/AngelP17/Astraea/actions/workflows/ci.yml/badge.svg)](https://github.com/AngelP17/Astraea/actions/workflows/ci.yml)
[![Deploy](https://github.com/AngelP17/Astraea/actions/workflows/deploy.yml/badge.svg)](https://github.com/AngelP17/Astraea/actions/workflows/deploy.yml)

Deterministic operational decision infrastructure for industrial telemetry. Astraea turns machine events into explainable actions, stage hashes, replay verification, and audit artifacts.

The project is intentionally claim-driven: every public claim should map to code, tests, and a generated artifact in [docs/CLAIM_MATRIX.md](docs/CLAIM_MATRIX.md).

## Current Status

| Claim | Status | Evidence |
|-------|--------|----------|
| Determinism 100% | Verified | Stable bundle hash and per-stage hashes across repeated runs |
| Replay verified | Verified | Replay re-executes the original event and compares stored vs recomputed hashes |
| Every stage produces a SHA256 hash | Verified | Seven canonical stages emit individual hashes |
| Audit complete | Verified | Event, feature, assessment, decision, execution, consequence, and audit snapshots are stored |
| Streaming mode | Measured | SSE demo stream follows the seven canonical stages |
| Benchmark metrics | Measured | Generated from `uv run python -m backend.evaluation.run_eval` |
| Graph-lite cascade reasoning | Partial | Graph engine is wired into demo/session context, not single-event inference |
| Deterministic ML inference | Verified | Frozen logistic model artifact and model card are generated by the eval harness |
| Floci cloud path | Partial | Optional local emulation hooks exist; production deployment is not claimed |

## What It Does

1. Ingests industrial machine events.
2. Extracts deterministic features.
3. Scores risk with a frozen deterministic logistic model.
4. Prioritizes the case and decides whether to route to human review or incident handling.
5. Estimates consequence and operational exposure.
6. Emits a hash-bound audit record.
7. Replays stored cases by re-running the original event and comparing hashes.

## Architecture

### Seven-Stage Deterministic Pipeline

```mermaid
flowchart LR
    A[Ingestion] --> B[Feature Extraction]
    B --> C[Frozen ML Inference]
    C --> D[Prioritization]
    D --> E[Execution]
    E --> F[Consequence]
    F --> G[Audit]
```

Each stage produces a SHA256 hash. The final deterministic hash is computed from the canonical sorted-key JSON bundle.

## Product Surfaces

- `/` shows the proof-first landing console.
- `/engine` inspects stored cases and replay verification.
- `/evaluation` renders measured evaluation output and the claim-to-proof matrix.
- `/architecture` shows topology, health, and graph/session context.

If the backend is offline, the frontend shows an explicit offline state. It should not fabricate hashes, replay results, or benchmark numbers.

## Quick Start

```bash
git clone https://github.com/AngelP17/Astraea
cd Astraea
git config core.hooksPath .githooks
```

Install and run the frontend:

```bash
npm install
npm run dev
```

Install and run the backend:

```bash
uv sync
uv run uvicorn backend.api.main:app --reload
```

Open `http://localhost:3000`.

## Environment

Copy `.env.example` to `.env` and set values as needed:

- `DATABASE_URL` for PostgreSQL persistence
- `SECRET_KEY` for JWT signing
- `NEXT_PUBLIC_API_URL` for the frontend-to-backend API origin
- `ARTIFACTS_*` settings for artifact retention
- `FLOCI_*` settings only when using optional local Floci emulation

The Floci path is currently documented as optional local cloud emulation, not production deployment. See [docs/deployment/floci.md](docs/deployment/floci.md).

## Limitations

- Current event data is generated synthetic industrial telemetry.
- The frozen model is trained and evaluated on generated synthetic telemetry.
- The deterministic scoring path remains as a baseline/fallback.
- Graph reasoning is wired into demo/session context, not every single-event pipeline result.
- Benchmarks are reproducible local synthetic benchmarks, not external plant throughput claims.
- Replay verification is stable for the same software version and deterministic code path.
- Optional Floci support is local emulation until real deployment evidence exists.
